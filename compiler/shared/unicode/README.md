# `compiler/shared/unicode/`

Generated Unicode tables. **Architecture-neutral** — these survive the eventual
aarch64/riscv64 ports even though `compiler/x86_64/` does not.

Generated by `tools/ucd-gen/gen.py` from UCD **17.0.0**, pinned via
`nixpkgs#unicode-character-database` (ADR 0004). The generator is Python and is
**never on the build path**: `make` needs only fasmg (spec §18.1). The blobs are
checked in; CI regenerates and diffs them byte-for-byte (§11).

## Table format

Little-endian throughout, `incbin`'d via `tables/tables.inc`, which also carries
the counts as assemble-time constants.

**Two-stage tries** (`ccc`, `xid`) — stage 1 is `u16[8704]` block indices;
stage 2 is deduplicated 128-entry `u8` blocks. Lookup is
`stage2[stage1[cp >> 7] * 128 + (cp & 127)]`: two loads and some shifts, which
is the point of choosing a trie over anything cleverer.

| table | value |
|---|---|
| `ccc` | canonical combining class |
| `xid` | bit 0 = `XID_Start`, bit 1 = `XID_Continue` |

**Sparse sorted arrays** (`decomp`, `compose`) — binary search, not hashing. A
hash table would be smaller and would make iteration order depend on the hash
function, which §9.3 forbids for anything that can reach output.

- `decomp_keys` `u32[2081]` sorted codepoints; `decomp_vals` `u32` packed as
  `(pool_offset << 8) | length`; `decomp_pool` `u32` the sequences.
- `compose_keys` `u64[965]` sorted `(first << 32) | second`; `compose_vals`
  `u32` the composed codepoint. Composition exclusions and singletons are
  already removed, so a hit is unconditionally valid.

Hangul is algorithmic (UAX #15 §3.12) and deliberately absent — storing 11,172
syllables would be waste.

## Verified

- **NFC: 100,170 `NormalizationTest.txt` assertions pass, 0 fail.**
- Generator is deterministic: identical output across divergent working
  directory, `TZ`, locale, `PYTHONHASHSEED` and umask.
- The checked-in blobs reproduce byte-for-byte from a fresh run.

## Not here yet

- **`confusables.txt` (UTS #39), backing `EXS-E0105`.** It is *not* in the core
  UCD and nixpkgs has no `unicode-security` package, so it is not currently
  obtainable hermetically. `EXS-E0105` is scoped to the import closure (§8.2)
  and lands with the `ego` reader rather than the lexer, so this blocks nothing
  yet. It will need vendoring or a fetch app on the `apps.vendor-fasmg-x86`
  pattern. `[OPEN]`
- Grapheme segmentation tables (§11, `grapha` in §5.1).
- The assembly consumers. These are tables; `nfc.inc`, `xid.inc` and
  `confuse.inc` need `rt/`, which is still being written.
