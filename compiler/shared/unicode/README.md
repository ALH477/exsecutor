# `compiler/shared/unicode/`

Generated Unicode tables, and the assembly that reads them.
**Architecture-neutral** — these survive the eventual aarch64/riscv64 ports
even though `compiler/x86_64/` does not. (The three `.inc` files are x86-64
assembly and do not; the *tables* are the part §18.2 names as portable.)

Generated by `tools/ucd-gen/gen.py` from UCD **17.0.0**, pinned via
`nixpkgs#unicode-character-database` (ADR 0004). The generator is Python and is
**never on the build path**: `make` needs only fasmg (spec §18.1). The blobs are
checked in; CI regenerates and diffs them byte-for-byte (§11).

## The consumers

| file | provides | spec |
|---|---|---|
| `nfc.inc` | `nfc_ccc`, `nfc_decomp_of`, `nfc_compose_pair`, `nfc_decompose`, `nfc_quick_check`, `nfc_normalize`, `nfc_is_nfc` | §8.1 (`EXS-E0102`) |
| `xid.inc` | `xid_flags`, `xid_start`, `xid_continue` | §8.2 |
| `script.inc` | `script_of`, `script_resolve` | §8.2 (`EXS-E0104`) |

All three work on **codepoint arrays** (`u32`), never UTF-8 bytes — decoding
belongs to the lexer, which does it anyway while scanning. None of them emits a
diagnostic or decides policy; they answer questions.

### How to include them

`tables/tables.inc` is **not** included from any of the three. A consumer
includes it itself, exactly once, in a data segment of its choosing:

```fasmg
include '<...>/compiler/shared/unicode/nfc.inc'      ; code, any order
include '<...>/compiler/shared/unicode/xid.inc'
include '<...>/compiler/shared/unicode/script.inc'
...
segment readable                                     ; read-only data
  include '<...>/compiler/shared/unicode/tables/tables.inc'
```

`tables/tables.inc` defines labels and emits ~120 KB of `file` data, so
processing it twice is fatal; including it from each module would break any
consumer that wanted two of the three. The macro files each module *does*
include (`macros/proc.inc`, `macros/assert.inc`) define only macros, and fasmg
permits macro redefinition, so the three-way overlap is harmless — verified by
`tests/unit/unicode_modules.asm`, which includes all three modules at once.

### Names these modules reserve — read this before naming a label

`macros/proc.inc` binds every `proc` argument and `slot` name as an
**unmangled global** (its own header explains why). Including any of these
three files therefore reserves these names across your whole translation unit:

```
a  b  cp  dst  dstcap  scratch  scratchcap  src  srclen
```

plus the routine names themselves (`nfc_*`, `xid_*`, `script_*`) and the
`UNI_*` constants from `tables.inc`. A consumer that declares a data label by
one of the reserved names fails with

```
Error: definition of 'srclen' in conflict with already defined symbol.
```

pointing at **the consumer's** line, with nothing in the message naming the
module that reserved it. Found by running, not by reading:
`tools/ucd-gen/nfc_conformance.asm` declared `srclen dq 0` and hit exactly
this. Prefix your own data labels (`lex_srclen`, not `srclen`).

## Table format

Little-endian throughout, `incbin`'d via `tables/tables.inc`, which also carries
the counts as assemble-time constants.

**Two-stage tries** (`ccc`, `xid`, `script`) — stage 1 is `u16[8704]` block
indices; stage 2 is deduplicated 128-entry `u8` blocks. Lookup is
`stage2[stage1[cp >> 7] * 128 + (cp & 127)]`: two loads and some shifts, which
is the point of choosing a trie over anything cleverer.

| table | value |
|---|---|
| `ccc` | canonical combining class |
| `xid` | bit 0 = `XID_Start`, bit 1 = `XID_Continue` |
| `script` | primary Script property id; `UNI_SCRIPT_ZZZZ` (Unknown) is the default |

**Sparse sorted arrays** (`decomp`, `compose`, `scriptext`) — binary search, not
hashing. A hash table would be smaller and would make iteration order depend on
the hash function, which §9.3 forbids for anything that can reach output.

- `decomp_keys` `u32[2081]` sorted codepoints; `decomp_vals` `u32` packed as
  `(pool_offset << 8) | length`; `decomp_pool` `u32` the sequences. Offsets are
  in u32 **elements**, not bytes.
- `compose_keys` `u64[961]` sorted `(first << 32) | second`; `compose_vals`
  `u32` the composed codepoint. All three UAX #15 exclusion classes are
  already removed — singletons, `CompositionExclusions.txt`, and **non-starter
  decompositions** (`ccc(left) != 0`) — so a hit is unconditionally valid and
  `nfc_compose_pair` can be handed any pair at all. The third class was
  missing until this wave and let four pairs through (`U+0308+U+0301`,
  `U+0F71+U+0F72/0F74/0F80`); see `gen.py`'s `emit_compose` docstring for the
  root cause, and `tests/unit/nfc_normalize.asm` rows 8–11 for the regression
  guard. Swept after the fix: 0 of 961 pairs has a non-starter left operand.
- `scriptext_keys` `u32[669]` sorted codepoints; `scriptext_vals` `u32` packed
  as `(pool_offset << 8) | count`; `scriptext_pool` `u8` the script ids.
  Offsets here are in **bytes**. Every entry's id list is sorted ascending with
  no duplicates, the longest is 23 (`UNI_SCRIPTEXT_MAX_COUNT`), none contains
  Common or Inherited, and none is merely `[primary script]`.

Script ids are one per registered ISO 15924-shaped short code (176 in UCD
17.0.0), numbered 0.. in alphabetical order — a fixed, hash-free order.

Hangul is algorithmic (UAX #15 section 3.12) and deliberately absent — storing 11,172
syllables would be waste. `nfc.inc` implements the L/V/T arithmetic in both
directions.

## Verified

Every number here was produced by a command that ran; nothing is an estimate.

- **The checked-in blobs reproduce byte-for-byte from a fresh run** —
  `gen.py --ucd <pinned UCD> --out <tmp>` then `diff -r`, all 15 files
  identical.
- **NFC, Python reference: 100,170 `NormalizationTest.txt` assertions pass, 0
  fail** (`gen.py` runs this on every invocation). This validates the *tables*.
- **NFC, the shipping assembly: 100,170 records pass, 0 fail** — the same
  corpus driven through `nfc_normalize`/`nfc_is_nfc`/`nfc_quick_check`
  themselves, by `tools/ucd-gen/nfc_conformance.asm`. `nfc_quick_check`
  produced 0 false YES and 0 false NO across all of them. This validates the
  *code that reads the tables*, which is a different program. That file's
  header carries the exact three-command recipe. Run again unchanged after the
  compose-table fix (965 → 961 entries), which was a prediction and is now a
  measurement.
- `nfc_quick_check`'s derived `Full_Composition_Exclusion` set is exactly UCD
  17.0.0's `NFC_QC=No` set: 1120 members, no difference in either direction,
  over all 0x110000 codepoints. Re-derived against the corrected table.
- Generator is deterministic: identical output across divergent working
  directory, `TZ`, locale, `PYTHONHASHSEED` and umask.
- Five `tests/unit/` fixtures cover the consumers: `xid_props.asm`,
  `script_lookup.asm`, `nfc_normalize.asm`, `unicode_modules.asm` (all three
  modules in one translation unit) and `unicode_range_release.asm` (the
  out-of-range path with `RELEASE` defined). Each was checked with a
  deliberately mutated copy first, so a green run means the checks are live.

## Not here yet

- **`confusables.txt` (UTS #39), backing `EXS-E0105`.** It is *not* in the core
  UCD and nixpkgs has no `unicode-security` package, so it is not currently
  obtainable hermetically. `EXS-E0105` is scoped to the import closure (§8.2)
  and lands with the `ego` reader rather than the lexer, so this blocks nothing
  yet. It will need vendoring or a fetch app on the `apps.vendor-fasmg-x86`
  pattern. `[OPEN]`
- Grapheme segmentation tables (§11, `grapha` in §5.1).
- An **`NFC_QC` trie**. `nfc_quick_check` derives NFC_QC from the `decomp` and
  `compose` tables (correctly — the derived set is exactly UCD 17.0.0's
  NFC_QC=No set, all 1120 members), at the cost of one or two binary searches
  per codepoint where a trie would cost one load. Adding it means regenerating
  every blob, and nothing has yet shown the cost matters. `[OPEN]`, and not a
  known win.
- **Skeleton computation** (UTS #39). §8.2 names it alongside the script data;
  it needs `confusables.txt`, so it waits on the same `[OPEN]`.
